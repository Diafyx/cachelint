# cachelint 0.2.0a1

First 0.2 alpha release of the offline `cachelint` analyzer. It supports Python
3.11 through 3.14 and has no required runtime dependencies.

## New in this release

- `analyze_corpus` reads explicit JSONL files or recursively discovered JSONL
  directories, groups requests by provider and exact model, and returns
  per-cohort comparisons. The result omits model strings and source paths.
- Ranked `CorpusPattern` records count recurring modeled prefix differences
  across cohorts. Cohort summaries distinguish identical and divergent pairs,
  context changes, limited coverage, and insufficient evidence.
- `cachelint corpus PATH...` prints a text report or a versioned JSON report.
  `--format json --output report.json` writes the complete report atomically.
  The bundled `corpus_report_v1.schema.json` defines the machine-readable
  contract; `cachelint.report.corpus_report` exposes the same projection to
  Python callers.
- CI now smoke tests the corpus command and report from both the wheel and
  sdist outside the checkout.

After publication, install the exact prerelease with
`python -m pip install cachelint==0.2.0a1`. The existing optional tokenizer and
pinned SDK recording extras remain available. See the [corpus guide](../corpus.md)
for command and Python examples, and the [README](../../README.md) for setup.

## Ordering, privacy, and limits

The first request in normalized file path and physical line order is the fixed
reference for each cohort. Every later row is one observation, including
duplicates. Recording timestamps do not reorder rows. Patterns rank by
descending observed count, then earlier complete-segment divergence, cohort
index, safe path, and difference kind. Token lengths are advisory estimates
of modeled content. Request bodies do not provide reliable provider-reported
cache usage, so equality never proves a cache hit and a difference is not a
measured cache miss.

Default bounds are 128 files, 16 MiB of input bytes, 20,000 nonblank requests,
and 4,096 discovery entries. The API and CLI allow explicit bounds. Discovery
rejects symlinks and duplicate normalized files. Invalid input returns no
partial result or report. Reports omit raw values, excerpts, model strings,
source paths, and persistent content hashes, but counts and length estimates
are still operational metadata. Error messages can include local input paths
and line numbers. Protect recordings and reports under your retention and
access policy.

Named report output replaces an existing file only after successful analysis.
The parent directory must exist; symlink destinations, direct input files,
and `.jsonl` output names are rejected. Opaque content and unmodeled context
can limit the diagnosis. The JSON schema is version 1; later incompatible
report changes require a new version.

## Migration and compatibility

Users of `0.1.0a3` can keep using `analyze`, `diff`, `compare_requests`, and the
opt-in SDK recorder without changing calls. The corpus API, command, and JSON
report are additive. Code adopting the new API should treat cohort indexes as
local to a result: adding an earlier-sorted cohort can renumber later cohorts.
Do not interpret observed counts as independent cache events, especially when
recordings contain retries or duplicates.

The package makes no provider API calls during analysis. As an alpha release,
the new corpus API can evolve in later prereleases with documented migration
notes. PyPI publication and verification remain tracked by the open release
issue until all release checks are complete.
