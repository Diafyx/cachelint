# cachelint 0.2.0a2

This prerelease adds opt-in provider cache-usage evidence to the offline
analyzer. It supports Python 3.11 through 3.14, has no required runtime
dependencies, and retains the existing request-only commands and report v1.

## New in this release

- The pinned Anthropic Messages (`anthropic==1.8.0`) and OpenAI Chat
  Completions (`openai==3.37.0`) recorders can capture allowlisted response
  usage counters in a separate private `.usage.jsonl` sidecar. Recording
  remains off by default. The raw request JSONL format stays unchanged.
- `analyze_usage` and `cachelint usage` validate same-session request and
  sidecar pairs by exact byte offset. Their version 1 report separates
  positive, zero, and unknown cache-read counts; Anthropic cache-write counts
  are available when reported. OpenAI writes remain unknown under this pinned
  recorder contract. Retries are distinct attempts, and unmatched attempts
  are counted without attaching them to a request.
- `analyze_observed_corpus` and repeatable `cachelint corpus --usage-trace
  PROVIDER REQUESTS SIDECAR` combine validated observations with modeled
  prefix patterns. The opt-in corpus report uses bundled schema v2, with
  per-cohort usage summaries and ranked findings that separate observation,
  plausible causes, and actions. Request-only corpus reports remain schema v1.
- The CI and release package checks smoke-install both SDK extras and run
  synthetic usage and corpus examples from installed packages outside the
  checkout.

Install the exact prerelease after publication with
`python -m pip install cachelint==0.2.0a2`. For recording, install the
appropriate extra: `cachelint[sdk-anthropic]==0.2.0a2` or
`cachelint[sdk-openai]==0.2.0a2`. See the [recording guide](../recording.md),
[usage guide](../usage.md), and [corpus guide](../corpus.md) before enabling
private capture.

## Evidence and privacy

Anthropic read and write observations come only from its documented
`cache_read_input_tokens` and `cache_creation_input_tokens` response fields.
OpenAI read observations come only from
`prompt_tokens_details.cached_tokens`. Missing rows or counters are unknown,
never cache misses. Known token totals are partial when unknown values exist.
The sidecar is private operational data; store it with its request file in a
protected directory, retain it only as needed, and never commit it. Successful
reports omit request values, model strings, source paths, response IDs, and
persistent content hashes. Local error messages can include private paths.

A zero read alongside a matching modeled prompt is an observation, not proof
of expiry or any particular provider behavior. A positive read alongside a
modeled divergence may reflect reuse before that divergence. Local prefix
estimates and bundled cache thresholds are advisory. Observed counters do
not reveal a provider's private cache key or which prompt bytes were reused.
The package makes no provider API calls during offline analysis and reports
no prices, savings, or guaranteed hits.

## Migration and compatibility

Existing `analyze`, `diff`, `compare_requests`, `analyze_corpus`, and
request-only `cachelint corpus` calls need no migration. `corpus_report` emits
v1 for `CorpusResult` and v2 only for `ObservedCorpusResult`. Consumers that
adopt sidecars should select parsing by `schema_version`, keep paired files
from the same recorder session unchanged, and treat unknown counters as
unknown. Recursive corpus discovery now skips `.usage.jsonl` sidecars; a
direct sidecar path is rejected as a request input.

The release issue remains open through publication and independent artifact,
provenance, installation, and GitHub prerelease verification.
