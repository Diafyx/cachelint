# cachelint 0.3.0a1

This prerelease adds offline diagnosis of recurring modeled prompt-prefix
differences in Anthropic Messages and OpenAI Chat Completions request bodies.
It supports Python 3.11 through 3.14 and has no required runtime dependencies.

## New in this release

- `cachelint diagnose` reads bounded JSONL files or directories, groups requests
  by provider and exact model, and ranks fixed-code findings with safe paths,
  evidence levels, counts, explanations, and suggested next actions.
- `diagnose_requests` classifies one canonicalized cohort; `analyze_diagnosis`
  applies it to a corpus. Both compare later requests with the cohort's first
  request. The CLI and Python API use the same deterministic report contract.
- Supported causes include valid timezone-qualified timestamp changes,
  UUID-shaped identifier changes, reordered identical tools, whitespace drift,
  and changed text before a stable suffix. Context changes, unsupported
  content, insufficient data, and other differences receive explicit limited
  findings rather than a specific cause claim.
- Diagnosis report schema v1 (`cachelint.diagnosis`) is bundled in the wheel and
  sdist. A synthetic two-provider example and installed-package smoke test
  exercise the CLI, Python API, and schema from both distributions.

After publication, install the exact version with
`python -m pip install cachelint==0.3.0a1`. See the
[diagnosis guide](../diagnosis.md) and
[decision record](../design/0007-prefix-drift-diagnosis-contract.md) before
using findings to change private request construction.

## Migration and compatibility

No migration is required from 0.2.0a3. Existing comparison, corpus, usage,
baseline, and regression commands and Python APIs retain their documented
behavior. Their serialized schemas retain their own versions. Diagnosis report
v1 is a separate contract; consumers should select it by `report_type` and
`schema_version` and reject unknown versions. The existing optional extras
retain their names and pinned SDK versions.

The first request in each cohort is a fixed reference. Findings describe that
relationship, not all request pairs. Cohorts are grouped by exact model but
the report omits model names. A finding labeled `observed` describes a local
request difference, `candidate` suggests an investigation, and `limited`
marks insufficient or unsupported evidence. None establishes a provider cache
hit or miss. Cachelint cannot observe provider routing, TTL state, complete
cache-key rules, or historical cache state. A safe path or count can still
reveal workload shape; review reports before sharing.

## Privacy and release verification

The diagnosis report contains no prompt values, excerpts, source paths, model
names, request identifiers, or persistent content hashes. Keep source JSONL
and SDK recordings private. The classifier has explicit file, byte, request,
segment, node, text, and work limits; invalid input fails without a partial
report. It makes no provider API calls and makes no price, savings, or
guaranteed-hit claims.

The release issue stays open until the exact candidate, retained wheel and
sdist bytes, PyPI provenance, fresh-install diagnosis behavior, and GitHub
prerelease attachments are independently verified.
