# cachelint 0.2.0a3

This prerelease adds reviewable corpus baselines and opt-in regression gates for
CI. It supports Python 3.11 through 3.14 and has no required runtime
dependencies. Existing request-only and observed-usage analysis remains
available.

## New in this release

- `cachelint baseline create` projects corpus report v1 or v2 into a version 1
  baseline with deterministic ordering and no prompt values, model names,
  source paths, response IDs, or persistent content hashes. `baseline inspect`
  validates and displays the reviewed projection.
- `cachelint baseline check BASELINE CURRENT_REPORT --policy POLICY` compares
  selected per-cohort counts or advisory prefix estimates. Policy schema v1
  requires an explicit metric, direction, nonnegative tolerance, and severity
  for every rule. Missing cohorts, incomparable providers, and unavailable
  metrics have separate configurable actions. The default has no metric gates.
- The check exports a version 1 JSON regression report and an optional bounded
  Markdown summary through `--summary-output`. Error findings return status
  `3` after writing the reports; warning-only results return `0`. Invalid
  inputs return `2`, and unexpected failures return `1`.
- A maintained [CI example](../ci-regression.md) uses synthetic Anthropic and
  OpenAI requests, a reviewed baseline, and an explicit policy. Package checks
  exercise passing, failing, and invalid-input cases from installed wheel and
  sdist builds outside the checkout.

After publication, install the exact version with
`python -m pip install cachelint==0.2.0a3`. The prior optional extras retain
their names and pinned SDK versions. See the [baseline guide](../baselines.md),
[policy guide](../regression.md), and [CI example](../ci-regression.md) before
using a gate with private recordings.

## Migration and compatibility

There is no required migration from 0.2.0a2. Existing CLI commands and Python
APIs retain their behavior. Baselines, policies, and regression results are
new, versioned contracts; consumers must select them by their own
`schema_version` and reject unknown versions. Corpus report v1 remains the
request-only format, and v2 remains the opt-in observed-usage format. A v1
baseline has unavailable usage metrics rather than zero-valued usage.

Regression rules compare cohorts by numeric index and provider. The baseline
omits model identity and content fingerprints, so equal indexes do not prove
the same model or workload composition. Recreate and review a baseline when
the corpus changes. A selected positive read is provider-reported evidence,
but it does not identify reused bytes; modeled prefix equality does not prove
a provider cache hit. Counts are not normalized for workload size, and prefix
estimates made with different methods are incomparable. Unknown observed
usage is not a zero read or a miss.

## Privacy and release verification

Baseline, regression JSON, and Markdown outputs contain safe fields and fixed
finding codes, but counts and cohort shape can still be sensitive. Keep raw
JSONL, usage sidecars, and full corpus reports in a protected workspace; review
safe outputs before sharing. The CI example uploads only regression JSON and
Markdown, with one-day artifact retention. Offline checks make no provider
API calls and make no price, savings, or guaranteed-hit claims.

The release issue stays open until the exact candidate, retained wheel and
sdist bytes, PyPI provenance, fresh-install behavior, and GitHub prerelease
attachments are independently verified.
